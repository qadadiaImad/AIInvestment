## 2. SEC XBRL — interest income + exact receivables

**New module `scripts/aiinvest/xbrl.py`** (REST, keyless, polite UA per SEC policy):
- CIK resolution from SEC's `company_tickers.json` (cached in `data/xbrl/`).
- `companyfacts(cik)` → extract `us-gaap:InvestmentIncomeInterest` (+ bank variants
  noted in the v1 research), `us-gaap:InterestExpense`,
  `us-gaap:AccountsReceivableNetCurrent` / `ReceivablesNetCurrent` — most recent
  annual + quarterly values, each stamped (retrieved_at, accession, fiscal period).
- Cache: `data/xbrl/<CIK>.json`, refreshed when older than 30 days or on `--force`
  (filings move quarterly; daily re-pulls are impolite).
- **New CLI `scripts/pull_xbrl.py`** over the 128-universe (rate-limited ≤10 req/s per
  SEC guidance; serial is fine), wired into `refresh_daily.py` guarded like the others.

**Engine changes (`halal.py`):**
- `inputs_from_metrics` gains optional `xbrl` record: exact `receivables` (replaces
  the turnover proxy when present — envelope `basis` says which was used) and
  `interest_income`.
- Impermissible-income test: `activity_pct` becomes
  `curated_pct + (interest_income / total_revenue × 100)` (capped at 100) when
  interest income is known — the streams are distinct by construction (curated
  entries document segment-based non-interest revenue only, so no double-count) —
  implementing AAOIFI 3/4/4 "irrespective of source" and resolving the
  pre-revenue-quantum names from `insufficient_data`/paradox to computed verdicts.
- Purification: impermissible income = curated-segment amount + interest income
  (when known) — per-share math unchanged.
- Convention #4 updated (AR proxy only as fallback); new convention #6: interest
  income from latest XBRL annual facts; absence → test falls back to curated-only
  with `basis` disclosed.

## 3. S&P Shariah + DJIM screens (leverage-only, post-2023 rules)

- **Avg-mcap series builder** in `halal.py`: from existing
  `web/public/data/prices/<SYM>.json` 5y series → month-end closes → trailing 36-month
  (S&P) and 24-month (DJIM) average close × implied current shares
  (`market_cap_basic / close`). **Convention #5 (disclosed): constant-shares
  approximation** — historical shares outstanding unavailable; error is the buyback/
  dilution drift.
- Two new RULESETS entries: S&P debt < 33% of avg-MVE-36m; DJIM interest-bearing debt
  < 33% of avg-mcap-24m; NPI < 5% incl. all interest (shares the §2 activity logic).
  Citations from the v1 research (May 2025 methodology editions via Wayback; re-check
  note stands).
- UI: two more chips + accordion sections; `/halal` explainer table gains both rows
  including the "cash+receivables screens removed 2023" fact (differentiator).
- Missing price series → both standards `unknown`, visible.

## 4. Purification calculator UI

- Client component on `HalalCard` + `/halal`: input shares held → `per_share × shares`
  = amount to purify, with the basis line and "insufficient data" passthrough.
  Pure client-side arithmetic on already-shipped fields; no new data.

## 5. Compliance-change alerts (provenance diffs)

- `export_halal.py` additionally snapshots to `data/halal/history/halal_<date>.json`
  (gitignored) and diffs today vs. the previous snapshot: any `overall` flip or
  per-test status flip → entry `{symbol, date, from, to, driver_test, old_value,
  new_value, threshold, inputs_asof}` appended to `web/public/data/halal_alerts.json`
  (rolling 90 days). Declared in `bundles.py` (optional, `_DAILY`).
- `/halal` gains a "What changed" feed rendering the worked before/after per alert.
  No push/email in this release — on-site + content-pipeline consumption only.
- First run with no history → empty alerts file, no error.

## 6. Verdict-card → carousel/reel content hook

Plugs into the existing factory at its two documented seams (higgs map, 2026-07-21):
- **New `higgs/_build_v4_halal.py`**: reads `halal.json` verdicts; renders 4:5 slides
  with the `_build_v4.py` HTML+Playwright idiom (`slide_hook`/`slide_bars`/
  `slide_takeaway`): hook = verdict badge + ticker story; data = AAOIFI tests as
  ratio-vs-threshold bars (new `mode:"halal"` semantics: bar = ratio, marker =
  threshold); takeaway = the number that decides it (e.g. WKEY 5.8× cash/mcap) +
  disclaimer excerpt. Output `v4_halal_{ticker}_{n}_{type}.png`.
- **Reel path**: `mode:"halal"` branch in `_build_reel_stock.py` `data()` +
  CFG entries; `make_reel.py`/manifest unchanged.
- **Story picker** `scripts/aiinvest/halal_stories.py`: ranks candidates — verdict
  flips (from alerts), extreme margins, business-vs-ratio surprises (INTU pattern) —
  returns top-N with the numbers that make the hook. Social-copy rails apply: no
  first person, "screens/analysts" attribution, never name a news source, educational
  disclaimer on takeaway slides, and **never render "haram" as an accusation head —
  verdict language stays methodology-framed** ("fails the AAOIFI debt screen").
- CLI: `python higgs/_build_v4_halal.py [--top N | --ticker TK]`.

## Testing & failure posture (all items)

TDD throughout: golden tests for avg-mcap math, XBRL extraction (fixture
companyfacts JSON incl. a bank), activity-pct max() logic, diff/alert generation
(fixture two-day snapshots), story ranking; vitest for calculator + alerts feed +
explainer; existing gates (provenance, bundle verifier, leak check) extended to
`halal_alerts.json`. Missing input anywhere → `unknown`/`insufficient_data`/empty
feed — never a silent pass, never a crash.

## Release order

activate later) → 2 XBRL → 3 S&P/DJIM → 4 purification UI → 5 alerts.
History snapshotting (item 5's store) starts with item 1's ship so alerts have
data the day they land.
